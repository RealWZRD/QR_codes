# QR Feedback

Інтерактивний дашборд для аналізу відгуків клієнтів, зібраних через QR-коди. Excel-файл завантажується і парситься прямо в браузері (без бекенду), далі — мульти-фільтри, часові ряди, агрегації по РМ/ТМ/містах/об'єктах та табличний звіт із дельтами.

## Що вміє

- **Два режими: Дашборд і Звіт** (перемикач у хедері)
- **Візуалізації:** часові ряди (день/тиждень/**місяць**) з можливістю розкласти на окремі лінії по всіх РМ або всіх ТМ; розподіл по днях тижня з кнопкою сортування; топ-N РМ/ТМ/міст; ФМ vs ФФМ; запит зворотного зв'язку; розподіл рейтингів 1–5
- **KPI-картки:** загальна к-ть, середній NPS, NPS Score (промоутери − детрактори), % зворотного зв'язку, середній рейтинг
- **Інтерактивні фільтри:** діапазон дат, мульти-вибір РМ/ТМ з пошуком, тип точки, діапазон NPS, чекбокси, drill-down по днях тижня / рейтингах / містах / об'єктах
- **Drill-down кліком:** клік на бар/смужку у Weekday / Rating / TopGroup / таблиці об'єктів фільтрує **весь дашборд**. **Shift+клік** додає/прибирає у мульти-вибір; звичайний клік = "тільки цей"
- **Табличний звіт:** порівняння по тижнях і місяцях з кольоровими дельтами (зелене — покращення, червоне — погіршення) + окрема таблиця "По об'єктах" з пошуком, lazy-load (30 рядків + кнопки "Показати ще" / "Прогрузити всі") та drill-down
- **Таблиця коментарів:** повнотекстовий пошук, пагінація, кольорове кодування NPS
- **Excel upload:** SheetJS парсить .xlsx у браузері — нічого не йде на сервер

## Формат вхідного Excel

Шукається аркуш `data_source` (або перший аркуш, якщо такого немає). Колонки знаходяться гнучко за частковим збігом назв (регістр і пробіли не мають значення):

| Поле в коді | Що шукається в заголовку |
|---|---|
| `date` | "дата" |
| `nps` | "nps" |
| `rating` | "рейтинг" |
| `location` | "об" (для "Об'єкт") |
| `comment` | "текст" → fallback "коментар" (але не та колонка, що ми вже взяли як `shopType`) |
| `contactBack` | "radio" або "зв" |
| `rm` | "рм" |
| `tm` | "тм" |
| `shopType` | "фм" у назві → fallback: **auto-detect** колонки, де ≥50% значень — `ФМ` або `ФФМ` |

**Дати:** `DD.MM.YYYY`, `DD.MM.YYYY HH:MM`, ISO `YYYY-MM-DD[Thh:mm]`, або Excel-серіали. Час відкидається. Рядки без валідної дати пропускаються.

**Міста** (для "Топ міст") нормалізуються через `normalizeCity()`: whitelist мульти-словних назв (`Кривий Ріг`, `Біла Церква`, `Жовті Води`, …) + typo-мапа (`Біла Цервка → Біла Церква`, `Київ Видубичі → Київ`). Покриває кейси, коли в адресі нема коми між містом і вулицею.

## Деплой на Vercel

```bash
npm install -g vercel
vercel login
vercel              # перший раз
vercel --prod       # подальші пуші
```

Vite-проект Vercel розпізнає автоматично: `npm run build` → `dist/`.

## Деплой на Netlify

1. Push коду в GitHub
2. На netlify.com → "Add new site" → "Import from Git"
3. Build command: `npm run build`
4. Publish directory: `dist`

Або через CLI:
```bash
npm install -g netlify-cli
netlify deploy --prod --dir=dist
```

## Як додавати нові графіки

1. Додай функцію агрегації у `src/lib/metrics.ts`
2. Створи компонент у `src/components/`, який приймає `rows: FeedbackRow[]`
3. Вмонтуй у `src/App.tsx` всередині `view === 'dashboard'` блоку — він автоматично отримає вже відфільтровані дані

## Як додавати нові фільтри

1. Розшир `Filters` у `src/types/feedback.ts`
2. Додай гілку у `applyFilters` у `src/lib/store.ts`
3. Додай UI у `src/components/FiltersPanel.tsx` (і чіп у блоку активних фільтрів)
4. Якщо це **drill-down з графіка** — використай хелпер `multiToggle()` зі `store.ts` для shift+click логіки
